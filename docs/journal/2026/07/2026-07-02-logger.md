# 2026-07-02 — Logger (roadmap 7.3, closes M7)

## What got done

- Implemented `it::d4np::util::Logger` (component #20): asynchronous multi-sink logger —
  the Milestone 7 closer and the largest component so far. Declarations plus the templated
  hot path in `logger.hpp`; everything else (pump, rendering, sinks, sockets, thread-id
  APIs) in `logger.cpp`, compiled into the ADR-0004 STATIC tier so `<winsock2.h>`/
  `<netdb.h>` never reach consumer TUs.
- **Design (ADR-0020):** eager call-site formatting (ADR-0012 `FormatString`, level filter
  before any work) → bounded monitor queue (one mutex, three CVs) → one dedicated pump
  thread renders each record once (UTC line) and fans out to a **Strategy** `Sink`
  hierarchy (`ConsoleSink`, `FileSink` binary/append, `UdpSink` numeric-literals-only).
  Explicit `OverflowPolicy` (`block` default / `drop` + `dropped()`); sink throws absorbed
  and counted (`sink_failures()`); `flush()` is a ticketed marker riding the queue
  (bypasses the capacity bound — a blocked flush could never be released by the pump it
  waits for); `shutdown()`/destructor drain, flush, join, idempotent.
- **Reentrancy guards:** a sink calling `flush()` — or a blocking `log()` on a full
  queue — on its own logger is diagnosed with `std::logic_error`. The pump's thread id is
  cached at construction: comparing against `pump_.get_id()` live would race the `join()`
  in `shutdown()`.
- Build wiring: `logger.cpp` joins the static tier, which now also links `ws2_32`
  (Winsock, Windows) and `Threads::Threads`. Tests join the `EGL_UTIL_BUILD_STATIC` group.
- Patterns catalogue: **Strategy** + **Producer-Consumer** adopted; **Monitor Object** and
  **Guarded Suspension** rows extended; **Active Object** recorded as rejected (data
  records, not method-request objects; no futures).

## Test notes

- Custom sinks observe delivery through caller-owned state, read only after
  `flush()`/`shutdown()` (their internal synchronization orders the reads); only
  `GateSink` — which deliberately blocks the pump to hold the queue full — carries its own
  lock. Overflow tests assert *bounds* (`dropped() >= 2` for 5 records through capacity 2
  plus at most one in flight), not exact counts: the pump's progress is timing-dependent.
- UDP receipt is asserted structurally (local send succeeds; `localhost` rejected as
  non-numeric): a receiving socket in the test would re-implement platform sockets, and
  datagram loss is invisible by contract anyway.
- Message parsing in the concurrency test uses `std::from_chars` — `cert-err34-c` bans the
  scanf family, and `cppcoreguidelines-pro-type-vararg` would fire on it too.
